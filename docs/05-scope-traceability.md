## Cross-cutting requirements

| Requirement | Implementation | Evidence |
|---|---|---|
| Conversation never blocks actions; multiple inputs while an action runs | Action Ledger (`concierge-core/actions/ledger.ts`): idempotency key per confirmation, `FOR UPDATE SKIP LOCKED`, one running action per conversation (partial unique index), leases; worker executes; reads served inline; results via Postgres LISTEN/NOTIFY → SSE | L 6/6 (25 concurrent confirmations → 1 action; reads during writes; 30 seat racers → 1 winner; retries idempotent); `concierge-core/test/events.test.ts` |
| Every write is confirmed once | `prepare_*` → `confirmationId` (TTL 5 min) consumed exactly once | C "expired confirmations… explained, not executed"; L |
| Vista-shaped, swap-able integration | `vista-client` only module to change; mock reproduces Apigee OAuth, OData, V1 result codes | M "rejects missing api key with fault envelope", "rejects expired token with the documented fault", OData suite (`odata.test.ts`); `docs/03-go-live-swap.md` |
| Portable to another architecture | Hono (Node/Bun/Workers), Postgres, no vendor SDK in core; Docker Compose; agent-as-code | `docs/01-solution-architecture.md` |
| Hand-over artefacts | OpenAPI (`/openapi.json`, `infra/openapi.json`), Postman collections, runbook, demo script | this folder |
