## New local review interface

`buildJourneyTransitionSuite(clockLocal)` authors paired EN/AR boundary tests with an explicit validated Dubai clock. `materializeSimulations` retains all-tool mocking and a fail-closed fallback. No Procedure state is invented in history. Native success criteria require the missing step before the first generated answer; simulators may not supply it as a corrective follow-up.

`auditJourneyTransitionEvidence(test, fullRawTranscript)` takes the matching source test and the complete provider transcript, including authored history. It excludes that history from success evidence, links results to exact request IDs, and checks call/result order, rejected/blocked/unexecuted evidence, no-action boundaries, complete family proposal and age provenance. The initial boundary ends at the first spoken answer or next user message, whichever comes first. The changed film's age check must precede proposal creation. It deliberately does not grade natural-language question quality or all conversational semantics; retain manual review and provider grades separately. The runner must independently verify that the authored prefix matches before applying its length boundary; conservative recognition of user consent/age paraphrases also needs manual review.

The suite contains 18 new cases (nine EN/AR pairs), including a separate single-owned-booking identity-confirmation sequence. It does not remove either live Rahul booking or alter the historical two-booking scenarios. All 58 external tools are mocked with a fail-closed fallback. The refund pair tests actual destination selection and a new preview, followed by refusal of the separate exchange; neither destination selection nor a preview is treated as an executed refund.

Local validation on 14 September: all 179 agent tests in 12 files passed, including 25 transition regression tests; agent TypeScript checking passed. These counts cover source/fixture validation, not a native agent run or live conversation acceptance.
